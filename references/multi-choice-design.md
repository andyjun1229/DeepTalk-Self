# 多题型混排设计

> 深度自我访谈 Web 应用的交互优化方案。基于 2026-07-27 实施结果。

## 问题

63 题纯自由输入 → 用户打字疲劳、完成率低。但要保持深度访谈的本质，不能全换成选择题（会变成问卷）。

## 方案：三种题型按问题性质混排

| 题型 | 占比 | 适合什么 | 交互方式 |
|------|------|---------|---------|
| **free** | ~60% | 故事型、反思型问题 | textarea（不变） |
| **choice** | ~35% | 事实型、有明确分类的问题 | 按钮组 + "其他/自己写" |
| **scale** | ~5% | 程度型、频率型问题 | 1-5 滑块 |

**关键设计：choice 题永远保留"其他"选项，选它后展开 textarea 自由输入。** 不给用户"被框住"的感觉。

## 分类逻辑

判断某道题适合什么类型，看它问的是什么：

- **事实/背景型** → choice：选项覆盖大部分可能答案，减少不必要打字
  - 例："你生长在什么样的家庭里？" → 独生/最大/最小/中间/其他
- **故事/反思型** → free：每个人答案独一无二，预设选项反而限制
  - 例："过去5年你觉得最正确的决定是什么？"
- **程度/频率型** → scale：只需要量化判断
  - 例："你有多少影响力？1-5分"

## 实现

### 数据层

- `questions` 表加 `answer_type` (choice|scale|free) 和 `choices_json` (JSON数组)
- 题库文件用 `**D1-A3.[choice]**` 标注，选项用 `- 选项文本` 缩进
- 不标注时默认 `free`

### 前端

- 根据 `current.answerType` 条件渲染不同输入组件
- choice：`grid grid-cols-2` 按钮组，选中高亮，选"其他"展开 textarea
- scale：`input[type=range]` 滑块 + 大号数字显示
- free：保留原 textarea

### API 无变化

答案仍以 `raw_answer` 字符串提交——choice 是选中项的文本，scale 是数字字符串，free 是用户输入。后端完全不用改。

## 初步数据

实施后 DB 验证：63 题中 20 choice + 3 scale + 40 free。构建通过。
