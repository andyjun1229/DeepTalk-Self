# 混合题型设计：降低访谈摩擦的三种输入方式

> 基于 DeepTalk Self Web App (2026-07-27) 的实际实现。

## 问题

63 题全部自由文本输入 → 完成率低（用户需要 2-4 小时纯打字）。

## 方案

三种题型混排，不破坏深度访谈本质：

| 题型 | 适合什么 | 占 63 题比例 | 实现 |
|------|---------|-------------|------|
| **free** (自由输入) | 故事型、反思型 | ~63% (40题) | textarea，保留原体验 |
| **choice** (快捷选择) | 事实型、背景型 | ~32% (20题) | 按钮组 + "其他"自由输入兜底 |
| **scale** (1-5 量表) | 程度型、频率型 | ~5% (3题) | range slider + 数值显示 |

## 关键设计决策

1. **choice 题永远配"其他"选项** — 不让用户感觉被框住。选"其他"后出现 textarea 自由输入
2. **scale 题用滑块而非下拉** — 视觉直观，手感好，符合移动端交互习惯
3. **题型透明展示** — 问题气泡显示 `[选择]` 或 `[1-5]` 后缀，用户知道这题不需要打字
4. **确认按钮统一** — 三种题型都用一个"确认"按钮提交，交互一致

## 题型分配原则

- **快捷选择**：答案有明确类别的（"你会先听谁的意见"→ 数据分析/直觉/别人建议）— 20 题
- **量表**：问强度/频率的（"1-5分，你有多少影响力"）— 3 题  
- **自由输入**：需要个人叙事和反思的（"你最正确的决定是什么"）— 40 题

实际 DB 验证（2026-07-27 seed）：
```
choice|20
free|40
scale|3
```

## 数据格式

前端根据 `answerType` 决定输入组件，后端始终收 `raw_answer` 字符串：
- choice: 选中项文本（或"其他"填写的文本）
- scale: 数字字符串 "1"-"5"
- free: 用户输入原文
